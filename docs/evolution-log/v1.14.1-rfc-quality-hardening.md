# RFC: 基座质量加固与 Studio 健壮性演进 (Quality Hardening)

- **基线版本**: `v1.13.1` (包含构建现代化与 183/184 特性)
- **目标版本**: `v1.14.1` / `v1.15.0`
- **状态**: Accepted (Phase 0 推演)
- **创建时间**: 2026-10-27

---

## 1. 背景与核心动机
在完成 Turborepo 现代化无常构建体系后，构建和单测日志中暴露出 6 项潜在的产品层与质量层暗坑（详见 `docs/backlog.md`）。本演进周期旨在消灭这些暗坑，确保系统具备金融级的健壮性与端到端的可观测性。

## 2. 关键架构决策 (ADR)
1. **浏览器/运行时边界隔离**：禁止前端出现任何 `node:*` 前缀模块，使用 Web API 替代。
2. **SvelteKit 适配器选型**：采纳 `@sveltejs/adapter-static`。理由：Studio 现由 MCP Server 统一托管静态资产或独立发布静态 SPA，静态适配器打包零 Node 运行负担，天然安全。
3. **可观测性闭环**：向量检索降级必须作为一级事件记录在 Trace 中，形成对 RAG 服务质量的主动监控。

## 3. 实施里程碑计划
- [ ] **Milestone 1**: 浏览器运行时脱敏与 SvelteKit Static 适配器落地 (P0)
- [ ] **Milestone 2**: 画布 A11y 警告消除与 RAG 降级可观测性闭环 (P1)
- [ ] **Milestone 3**: Studio 组件测试基准建立 (P1)
- [ ] **Milestone 4**: 依赖治理与 PR #197 闭环 (P2)
