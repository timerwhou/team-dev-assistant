# RFC: 现代化无常构建体系与任务拓扑架构演进

- **基线版本**: `v1.13.1`
- **目标发布版本**: `v1.14.0`
- **状态**: Accepted (Phase 0 推演确认)
- **归档时间**: 2026-10-26

---

## 1. 背景与痛点根因 (5 Whys)
在 `v1.13.1` 基线及历史分支中，项目长期受困于纯 `tsc` 构建模式：
1. **源码被工具反向污染**：为满足 NodeNext 静态解析，此前不得不强行在 40 多个源码文件中手动补充 `.js` 扩展名。
2. **跨分支灾难级合并冲突**：未合并的特性分支（如 `feat/story-184`、`feat/story-183`）未包含 `.js` 扩展名，导致后续代码合并面临 40+ 文件冲突。
3. **依赖拓扑断层**：子包构建缺少全局拓扑感知，分支被迫在 CI 中写死“前置构建 a2a”等脆弱 Hack 脚本。

---

## 2. 行业标杆对标与架构选型
对标 Vercel、tRPC、Prisma 等头部 Monorepo 体系，选定前沿的 **Turborepo 2.x + tsup (esbuild) + Bundler 模块契约**：

### 核心收益
1. **源码零污染**：统一使用 `"moduleResolution": "bundler"`，TypeScript 源码保持原生裸导入，彻底废弃手动 `.js` 侵入。
2. **构建速度从分钟级降至亚秒级**：基于 `esbuild` 多核并发，结合 TS 5.x 极速生成 `.d.ts`，彻底告别单线程 `tsc` 的性能瓶颈。
3. **无常增量缓存 (Deterministic Caching)**：Turbo 接管全局拓扑依赖，根据 Inputs/Outputs 哈希秒级还原产物。
4. **双特性分支 0 冲突保障**：不改动任何业务源码，仅改造构建契约配置，特性分支可一键 Rebase。

---

## 3. 标准化架构契约 (System Contract)

### 3.1 根目录 Pipeline 契约 (`turbo.json`)
```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "outputs": ["dist/**"]
    },
    "typecheck": {
      "dependsOn": ["^build"],
      "outputs": []
    },
    "test": {
      "dependsOn": ["build"],
      "outputs": []
    },
    "dev": {
      "cache": false,
      "persistent": true
    }
  }
}
```

### 3.2 子包条件导出与构建契约 (Package Exports)
```json
{
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "development": "./src/index.ts"
    }
  },
  "scripts": {
    "build": "tsup",
    "typecheck": "tsc --noEmit",
    "clean": "rimraf dist .turbo"
  }
}
```

## 5. 现场实测验证记录 (Oct 26, 2026)
- **环境**: Node v24.22.1 / pnpm 10.0.0 / TypeScript 7.0.2 / tsup 9.0.0
- **实测性能**: `@tda/core` 代码转译从纯 `tsc` 的数秒缩减至 **57ms**（提升两个数量级）。
- **关键架构结论**: 
  - 必须剥离 `rollup-plugin-dts`，避免与 TypeScript 7.0 Compiler API 产生断层。
  - 保持业务源码纯净（零 `.js` 扩展名），彻底解耦构建逻辑与业务逻辑，保障未合并分支平滑变基。
