# 版本演进与里程碑解耦

## 背景

ADR-0004 实施后，`feat` 会频繁触发 Minor 版本迭代。然而，一个大的里程碑（如 Context Engineering）包含多个 Story，导致同一个里程碑内产生多个 Release 版本，使得版本号与里程碑在长期演进中再次出现错位。

## 设计目标

- 明确版本号代表“发布批次”，里程碑代表“功能阶段”。
- 避免为了凑版本号而扭曲开发节奏。

## 架构设计

将项目阶段规划统一命名为 `Phase N`（如 Phase 3、Phase 4），不再使用 `v0.x.0` 作为里程碑前缀。版本号由 Release Please 根据提交历史自然生成。此外，在必要阶段总结时，允许使用 `Release-As: x.y.0` 强制切大版本。

## 影响评估

- **正向**：规划名称与实际发版解耦，符合行业主流实践。
- **负向**：需要团队改变“阶段 = 版本号”的固有认知。
